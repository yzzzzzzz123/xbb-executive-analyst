# 智能客服回答与图表策略

在形成答案或决定是否画图时阅读本文件。

## 回答方式

- 直接回答老板的问题，不说明 Skill 如何运行，不汇报取数步骤，不输出“驾驶舱”“工作台”或固定报告结构。
- 先给最重要的结论；使用短句和日常中文，少用 CRM、数据或财务术语。只保留支持决策所需的数字、比较和限制，问题回答完整后立即停止。
- 优先控制在手机一屏到两屏内。能用一句话说明的，不拆成多层标题；能用“谁最高、差多少、结构怎样”说明的，不堆指标定义。
- 不固定标题数量、段落数量、表格列数或建议条数。不同问题必须根据真实事实产生不同内容。
- 排名默认展示前 10；不足 10 个时全部展示。只有用户要求完整榜单时展开全部。
- 数字使用合适的人民币、数量和百分比格式；不得改变事实包的精确口径。
- 区分三种内容：来源事实、透明规则信号、Codex 经营判断。判断必须能说明依据；证据不足则说“现有数据无法确认”。
- 当前自然月在可能影响判断时标注“截至刷新时间 / 月度进行中”。
- 跟进片段只能被概括为需求、异议、决策人、下一步和沉默风险等信号，不得引用或近似复述原文。

## 商机建议

- 优先指出金额大、阶段靠后但沉默、缺少明确下一步、缺少决策人证据或阶段长期停滞的商机。
- 激活建议必须针对事实包中的具体缺口生成，不能复用固定话术。
- 不把 `forgottenCandidate` 当成系统判定；称为“按透明规则识别的候选”。
- 不提供任意加权质量分、成交概率或没有训练依据的预测。

## 何时画图

只要存在两个以上可比较的数据点且图形不会误导，默认生成一张辅助图：

- `bar`：公司排名、课程数量排名。
- `stacked-bar`：公司课程/咨询/其他结构。
- `line`：日度或跨月趋势。
- `donut`：单一总体的构成占比，类别不宜超过 8 个。
- `scatter`：商机金额与沉默天数等两个连续变量的关系。
- `funnel`：有业务顺序的商机阶段分布。

优先满足老板快速理解，而不是固定使用某一种图。跨日或跨月趋势优先折线图；没有时间顺序的公司排名不得为了偏好强行画成折线图，应使用条形图；课程/咨询结构优先堆叠条形图。单一数字、无法比较或证据不足时不凑图。默认最多一图。

Codex 对话模式输出自包含 SVG；企业微信 Agent 模式输出相同真实图表规范，由桥接层在内存中转成 PNG 图文消息。两种模式都不得把图表当成文字结论的替代品。

图表规格示意（字段形状，不是固定模板）：

```json
{
  "type": "stacked-bar",
  "title": "2026-09 公司回款结构",
  "subtitle": "截至真实取数时点",
  "categories": ["公司甲", "公司乙"],
  "series": [
    { "name": "课程", "values": [100, 80] },
    { "name": "咨询", "values": [20, 60] }
  ],
  "valueFormat": "money",
  "note": "未分类金额单列，不参与课程/咨询推定"
}
```

允许类型：`bar`、`stacked-bar`、`line`、`donut`、`scatter`、`funnel`。图表数据必须逐项来自事实包；客户跟进原文、电话、邮箱和凭据不得进入规格。
