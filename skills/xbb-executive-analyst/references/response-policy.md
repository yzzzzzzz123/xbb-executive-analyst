# 智能客服回答与图表策略

在形成答案或决定是否画图时阅读本文件。

## 回答方式

- 无论用户问什么，文字答复都是必需的，必须能独立回答问题；需要出图时交付“图片 + 文字”，不能只贴图、只说“见图/图表已生成”，也不能用图内文字代替正文。
- 回答详略随问题调整，推理强度与输出长度分开。只问单个数量、金额、名次或字段时，通常一至三句话直接给结果，保留必要单位、期间与口径；没有分析要求就不追加趋势、原因、建议或图表。
- 复杂、多条件或跨表问题合并原问题与仍有效追问，逐项给出判断、关键数字、比较及限制，最后说明有证据的维度联系。先核对时间、关联键、去重、分母、合计与排名；不能只答最后一句或总额。“图表呈现”“综合一点”继承原范围，不增加未问数据。不描述工具过程或套固定报告；大上下文不改变查询范围。
- 用户要求分析时，由事实到比较再到判断：在已请求指标内计算排名差距、集中度、结构差异、峰谷与同口径变化；明确关键异常及证据边界。只有事实支持时解释驱动或提出具体行动，不为写长而补查其他主题。
- “业绩好”限定为所问指标表现；缺少目标、利润或同比不能称综合经营最好。“其他组”归属待核，不自行排除。进行中月份标明截止日，不能与完整月直接判断回落。
- 用日常中文、合适单位和必要数字。完整回答优先于屏数；不固定标题、段落或建议条数。即使图中已有对应读数，正文仍须保留支撑结论的关键数字与比较，不必逐条复抄图中全部数据。
- 排名默认前 10；完整榜单以实际覆盖为准。年度已完整聚合时必须完成管理分析，不能回答“超过大小限制无法分析”；不把明细省略误报为月份缺失，不让用户拆主题重查。
- 严格区分来源事实、透明规则信号和模型判断；缺少证据就说明无法确认，不编造原因、概率、目标、利润或同期数字。
- 老板指标是职位严格等于“老板”的约课记录数；没有企业去重标识，不能称为企业家数。约课转化率是关联订单数÷约课记录数，不能称为企业成交率。
- 等待进度只描述已确认阶段，不披露业务明细或推理。跟进正文只提炼需求、异议、决策人、下一步和沉默风险，不引用或近似复述原文。

## 商机建议

- 优先指出金额大、阶段靠后但沉默、缺少明确下一步、缺少决策人证据或阶段长期停滞的商机。
- 激活建议必须针对事实包中的具体缺口生成，不能复用固定话术。
- 不把 `forgottenCandidate` 当成系统判定；称为“按透明规则识别的候选”。
- 不提供任意加权质量分、成交概率或没有训练依据的预测。

## 图片与经营图

凡是考虑生成辅助图，必须在同一轮调用 [xbb-executive-chart](../../xbb-executive-chart/SKILL.md)。该 Skill 是选图、数据充足性、排序、手机端信息层级和最小规格的唯一规则源；本文件不复制另一套映射。

企业微信必须保留完整文字答复，最多随附一张经营分析图片。两个及以上仍有效维度必须综合出图，宽泛经营问题也要出图；明确单一对象、期间、指标的标量问题可免图。主 Agent 原生委派 xbb_chart（gpt-6-astra/ultra）按辅助 Skill 先逐项分析，再生成综合图并交回复核，各维度对应子图和文字分析。用户明确不要图时遵从；事实不足的维度单独说明，不连带省略其他合格子图。图表与文字的期间、范围和数字保持一致。图片显示图形、精确读数、必要口径及通过 findings 引用计算的主发现与证据注释；不能用泛泛结论卡代替图。没有合格图或图表渲染失败时保留文字并说明具体原因，不发送占位图。

Codex 对话模式把合格规格渲染为自包含 SVG；企业微信 Agent 模式由桥接层按同一 Skill 合同在内存中转成 PNG，并对图表文字执行输出脱敏。两种模式都不得把客户跟进原文、电话、邮箱、凭据或任何模型自选样式放入规格或图片。
