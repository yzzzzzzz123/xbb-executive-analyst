# 销帮帮实时数据与经营口径

在选择数据域、解释指标或调整字段映射前阅读本文件。字段选项必须从实时表单定义解码，不能假设内部选项 ID 就是可见名称。

## 只读来源

| 数据域 | 表单 ID | 主要用途 |
|---|---:|---|
| 业绩/回款 | `6404920` | 公司业绩与课程/咨询结构 |
| OPP 订单 | `6707824` | 门票、前端产品数量与金额 |
| 课程 | `7452529` | 课程类型、日期、预约和成交 |

接口和字段白名单以项目公共实现 `shared/xbb/export-live-data.js` 为唯一实现。电话、邮箱和凭据字段不在白名单中；允许的自由文本会在进入来源包前脱敏并截断。

## 月份范围

- 业绩和 OPP 订单按各自业务日期 `date_1`。
- 课程按开始日期 `date_1`；约课记录按关联课程所在月份的当前导出范围。
- 商机按创建时间 `addTime`；因此商机分析表示“所选月份创建的商机”，不是所有历史存量商机。
- 跟进按跟进日期 `date_1`，用于分析同月创建商机在该月截至时点的跟进证据。
- 当前月是月初至实时刷新时点的 MTD 数据，不能表述为完整月结果。

## 确定性事实

### 业绩与收入结构

- 业绩金额：业绩回款表 `num_6`。
- 公司：业绩回款表 `text_3`。
- 课程/咨询：优先依据关联产品主数据。产品主数据接口没有返回记录时，只对业务记录产品名中明确出现的课程、训练营、咨询、顾问等关键词分类，并在事实中保留该依据；未明确命中的金额计入“其他”。
- 占比：分类金额 ÷ 同一公司或集团总回款金额。

### 门票、商业操盘和开源产品

- 门票：只统计 OPP 订单中产品主数据或业务记录产品名明确为门票/票务的销量；不能把全部 OPP 订单当门票。
- 商业操盘：只统计业绩回款记录中产品主数据或业务记录产品名明确包含“商业操盘”的售卖数量。
- 开源产品：优先使用产品前后端分类“前端/OPP”或产品分类 OPP；产品主数据不可用时，只有产品名明确包含“门票、OPP、开源”才纳入。
- 全部 OPP 订单的销量和金额另行作为 `oppOrderQuantity` / `oppOrderRevenue` 事实展示，不能与“已明确分类的门票”混为同一口径。
- OPP 订单与业绩回款缺少统一的跨表订单主键；两套开源产品数量和金额分别展示，不能相加后声称已经去重。
- 无法明确分类的数量和金额单列“未分类”，不得把全部 OPP 订单默认视为门票。

### 课程

- 课程堂数：开始日期落在所选月份的课程记录数。
- 参课老板/学员：关联约课表 `num_1` / `num_2` 求和。
- 参课企业：约课记录客户所属公司去重。
- 成交率：课程成交订单数 `num_6` ÷ 已预约客户数 `num_3`。签到字段未可靠同步时不能作为分母。
- 成交金额/已收金额：课程 `num_9` / `num_10`。
- 课程表当前没有可靠的组织公司字段。“某公司开课”只能按同一课程约课记录中订单所属公司的众数归为“主邀约公司”，答案必须说明这不是正式组织公司归属。

### 交付课程邀约与业绩

- 交付课程：课程类型包含“交付课程”且开始日期在所选月份。
- 邀约量：交付课程关联的约课记录数。
- 公司：按约课记录关联订单所属公司归集。
- 关联回款：同一公司内按关联订单 ID 去重后汇总约课记录金额 `num_3`。
- 该金额只是可追溯的“关联回款归集”，不能描述为财务分润、正式业绩分配或邀约/成交/交付三方权重。

### 商机与跟进质量

- “创建商机”按商机 `addTime` 和 `creatorId`；销售公司优先使用商机公司字段，缺失时才使用用户部门。
- 预计金额：`num_1`；赢单：阶段 `text_17` 为“赢单”；赢单金额：`num_14`，缺失时只能明确说明口径。
- 跟进优先通过关联业务直连商机；没有直连关系时回退到同客户关系。客户级回退可能命中同一客户的多个商机，必须保留限制。
- 事实层只给出阶段、金额、跟进次数、最后跟进日期、沉默天数、下一步动作信号、决策人信号和有效内容信号。
- “有效但被遗忘”候选规则：活动阶段、预计金额大于 0、存在中高意愿或有效跟进内容，并且至少 14 天未跟进。
- 不生成任意加权质量分，也不把规则信号描述为正式绩效、预测成交概率或系统认定。

## 证据边界

- 每个事实行保留来源 `evidenceRef`；回答通常无需展示内部 ID，但所有数字必须能回溯。
- 脱敏跟进片段只供当前 Codex 判断需求、阻力和下一步，不得逐字出现在最终答案或图表中。
- 没有客户级统一主键、正式分润字段、课程组织公司字段或完整产品分类时，必须明确说明无法确认。
