# 销帮帮实时数据与经营口径

在选择数据域、解释指标或调整字段映射前阅读本文件。字段选项必须从实时表单定义解码，不能假设内部选项 ID 就是可见名称。

| OPP 订单 | `6707824` | 门票、前端产品数量与金额 |

接口和字段白名单以项目公共实现 `shared/xbb/export-live-data.js` 为唯一实现。业绩订单先用合同订单列表接口按月定位，再逐条调用合同订单详情接口读取真实产品子表；课程举办方的部门 ID 只通过部门列表接口解码为公司名称。电话、邮箱和凭据字段不在白名单中；允许的自由文本会在进入来源包前脱敏并截断。

## 月份范围

- 业绩订单和 OPP 订单按签订日期 `date_1`。清单确认的稳定数据边界从 `2026-01-01` 开始；按用户所问上海自然月取数，不把 2026 年以来数据混入单月答案。
- 课程按开始日期 `date_1`；学员约课明细的 `text_5` 按课程数据 ID 逐课等值查询并关联当月课程，不批量拼成一个等值条件，也不使用未确认的约课日期推断课程月份。
- 商机按创建时间 `addTime`；因此商机分析表示“所选月份创建的商机”，不是所有历史存量商机。
- 跟进按跟进日期 `date_1`，用于分析同月创建商机在该月截至时点的跟进证据。
- 当前月是月初至实时刷新时点的 MTD 数据，不能表述为完整月结果。

## 确定性事实

### 业绩与收入结构

- 业绩金额：业绩订单产品明细 `array_4.num_5`（售价小计）求和。
- 公司：业绩订单 `text_63`（所属公司）。
- 课程/咨询：优先使用同一产品明细的 `array_4.text_10`（分类）；分类缺失时，才允许对 `array_4.text_1` 中明确出现的课程、训练营、咨询、顾问等关键词补充分类，仍无法确认的金额计入“其他”。
- 占比：分类金额 ÷ 同一公司或集团总业绩金额。若个别订单没有产品明细，只能用合同金额 `num_1` 保留总业绩，并把该笔结构计入“其他”，不能猜测课程或咨询分类。

### 门票、商业操盘和开源产品

- OPP 订单公司使用 `text_31`；产品名称和销售数量分别使用产品明细 `array_4.text_1`、`array_4.num_3`。
- 门票：只统计 OPP 订单产品名称明确为门票/票务的销量；不能把全部 OPP 订单当门票。
- 商业操盘：只统计业绩订单产品明细名称明确包含“商业操盘”的 `array_4.num_3`；“商业操盘”和“商业操盘复训”既给合计，也必须分开列出。
- 开源产品：产品名明确包含“门票、OPP、开源”时纳入；存在已解码的产品主数据分类时可作为补充依据，但不能用内部选项 ID 猜名称。
- 全部 OPP 订单的销量和金额另行作为 `oppOrderQuantity` / `oppOrderRevenue` 事实展示，不能与“已明确分类的门票”混为同一口径。
- OPP 订单与业绩回款缺少统一的跨表订单主键；两套开源产品数量和金额分别展示，不能相加后声称已经去重。
- 无法明确分类的数量和金额单列“未分类”，不得把全部 OPP 订单默认视为门票。

### 课程

- 课程堂数：课程开始日期 `date_1` 落在所选月份的记录数；课程名称为 `text_1`。
- 开课公司：课程举办方 `text_5` 的部门 ID 通过部门列表接口解码为公司名称；举办方缺失或无法解码时才允许回退到同课交付邀约订单所属公司的众数，并明确标注为回退口径。
- 参课老板：学员约课明细通过课程数据 ID `text_5` 关联课程，职位 `text_22` 为“老板”的记录数；所有职位可做构成，但不能把未知职位算成老板。
- 参课企业：只有约课记录存在可靠客户公司字段时才去重；清单未提供该字段时不得用约课记录数冒充企业数。
- 成交金额：业绩订单通过对应课程 `text_28` 关联课程，汇总合同金额 `num_1`。
- 成交率：使用“关联业绩订单数 ÷ 学员约课明细数”，并在答案中称为约课转化率。缺少任一可靠关联时保持为 0 并说明边界，不得用课程表旧汇总字段或未可靠同步的签到字段补算。

### 交付课程邀约与业绩

- 交付课程：课程类型包含“交付课程”且开始日期在所选月份。
- 邀约量：交付课程在交付邀约关联表 `7452855` 中的关联记录数；该表与课程分析使用的学员约课明细 `7642173` 分开，不能混成同一来源。
- 公司：按约课记录关联订单所属公司归集。
- 关联回款：同一公司内按关联订单 ID 去重后汇总约课记录金额 `num_3`。
- 该金额只是可追溯的“关联回款归集”，不能描述为财务分润、正式业绩分配或邀约/成交/交付三方权重。

### 商机与跟进质量

- “创建商机”按商机 `addTime` 和 `creatorId`；销售公司优先使用商机公司字段，缺失时才使用用户部门。
- 预计金额：`num_1`；赢单：阶段 `text_17` 为“赢单”；赢单金额：`num_14`，缺失时只能明确说明口径。
- 跟进优先通过关联业务直连商机；没有直连关系时回退到同客户关系。客户级回退可能命中同一客户的多个商机，必须保留限制。
- 事实层只给出阶段、金额、跟进次数、最后跟进日期、沉默天数、下一步动作信号、决策人信号和有效内容信号。
- “有效但被遗忘”候选规则：活动阶段、预计金额大于 0、存在中高意愿或有效跟进内容，并且至少 14 天未跟进。
- 不生成任意加权质量分，也不把规则信号描述为正式绩效、预测成交概率或系统认定。

## 证据边界

- 每个事实行保留来源 `evidenceRef`；回答通常无需展示内部 ID，但所有数字必须能回溯。
- 脱敏跟进片段只供当前 Codex 判断需求、阻力和下一步，不得逐字出现在最终答案或图表中。
- 没有客户级统一主键、正式分润字段或完整产品分类时，必须明确说明无法确认。
