# 销帮帮实时数据与经营口径

在选择数据域、解释指标或调整字段映射前阅读本文件。字段选项必须从实时表单定义解码，不能假设内部选项 ID 就是可见名称。

## 只读来源

| OPP 订单 | `6707824` | 门票、前端产品数量与金额 |

接口和字段白名单以项目公共实现 `shared/xbb/export-live-data.js` 为唯一实现。月度业绩订单先按签订日期定位，再逐条调用详情接口读取真实产品子表；课程成交订单使用同一表单但放入独立 `courseOrders` 集合，按当月课程 ID 与 `text_28` 逐课反查且不附加签订月份条件，两者不得混合。课程举办方的部门 ID 只通过部门列表接口解码为公司名称。电话、邮箱和凭据字段不在白名单中；允许的自由文本会在进入来源包前脱敏并截断。

## 月份范围

- 业绩订单和 OPP 订单按签订日期 `date_1`。清单确认的稳定数据边界从 `2026-01-01` 开始，早于该月份的业绩/产品查询必须拒绝。用户明确月份时按所问上海自然月取数；清单中的“集团业绩按公司排名并区分课程和咨询占比”若未写期间，默认取 `2026-01` 至当前上海月份，明确写了本月、当月或具体月份时以用户期间为准。
- 课程按开始日期 `date_1`；学员约课明细的 `text_5` 按课程数据 ID 逐课等值查询并关联当月课程，不批量拼成一个等值条件，也不使用未确认的约课日期推断课程月份。
- 商机按创建时间 `addTime`；因此商机分析表示“所选月份创建的商机”，不是所有历史存量商机。
- 跟进按跟进日期 `date_1`，用于分析同月创建商机在该月截至时点的跟进证据。
- 当前月是月初至实时刷新时点的 MTD 数据，不能表述为完整月结果。
- 今天、昨日或明确单日业绩使用 `date: YYYY-MM-DD`；源端按 `date_1` 限定上海该日零点至日末，今天上限为本次刷新时点。只支持 `performance`，`months` 仅该日所属月。事实包 `scope.date` 和 `range` 必须匹配请求，`currentDayPartial` 标识今天未结束，`currentMonthPartial=false`；不得把单日称为月累计，也不能把月累计当作今天。多日或混合日月范围未获支持时明确说明，不能默认为本月。

## 跨月与年度聚合

- 跨月查询仍按每个上海自然月独立实时取数和编译单月事实，再由 bundled runner 的确定性聚合器合并；模型不得对多个大 JSON 或被截断片段自行求和。
- 年度业绩的集团总额、课程/咨询/其他金额与占比、公司排名全部由各月同口径公司行相加后重新计算占比；月度走势直接使用每个单月 summary。
- 产品、课程、交付和商机同样先汇总完整月度指标及公司/人员排名。跨月模型包不携带逐条日趋势、完整课程列表、完整商机列表或跟进片段；这些属于按月份、公司或人员下钻的明细，不影响跨月管理汇总的完整性。
- `detailCoverage.aggregationComplete=true` 表示总额、计数、排名基础和月度趋势已覆盖全部所选月份；同时用数量字段明确说明下钻候选和原始明细是否进入模型包，不能把有界下钻候选说成原始数据截断。
- 跨月包最大为 128 KiB。达到边界必须在确定性聚合层依次压缩逐月 `provenance` 审计明细、重复的逐课职位结构、非汇总下钻候选和排名尾部；仍超限时只保留各域已声明的核心月度字段。`scope.months`、各域 `summary`、全部月份的核心趋势、核心排名至少前 10、完整的课程职位与商机阶段结构，以及各项覆盖计数必须保留。绝不能截断 JSON、丢月份后继续计算或要求模型凭不完整输入补齐。
- 逐月来源哈希和逐表记录数是本地审计材料，不是经营分析输入；跨月包可以只保留覆盖月份、刷新边界和整体完整性校验。它们的省略不得被解释为月份未查询或汇总不完整。

## 确定性事实

### 业绩与收入结构

- 业绩金额：只对业绩订单产品明细 `array_4.num_5`（售价小计）求和。缺少产品明细的订单进入完整性计数，但不得改用合同金额替代排名金额。
- 公司：业绩订单 `text_63`（所属公司）。
- 课程/咨询：只使用同一产品明细的 `array_4.text_10`（分类）归入课程、咨询或其他。分类缺失或无法归类时计入“其他”，不得根据产品名称猜测。
- 占比：分类金额 ÷ 同一公司或集团由售价小计构成的总业绩金额。

### 门票、商业操盘和开源产品

- OPP 订单优先使用需求清单结构：公司 `text_31`，产品名称和销售数量为产品明细 `array_4.text_1`、`array_4.num_3`。当前生产表可能以“一条记录一个产品”的扁平结构返回；只有实时字段目录同时明确标注 `text_6=所属公司`、`text_3=产品名称`、`num_1=产品销量/销售数量` 时，才允许使用这组三个字段，并以 `num_5` 作为该记录金额。不能只因子表为空就盲目回退。
- 门票：按需求清单，将 OPP 订单表 `6707824` 的销售数量作为成交门票数量；门票/开源产品的具体构成再按产品名称拆分。不得改用订单条数代替销售数量。
- 商业操盘：只统计业绩订单产品明细名称明确包含“商业操盘”的 `array_4.num_3`；“商业操盘”和“商业操盘复训”既给合计，也必须分开列出。
- 门票排名与商业操盘排名必须作为两套独立排序输出，不能用两者数量相加后的综合排序代替。
- 产品占比按“公司＋来源表＋产品”计算；数量占比和金额占比的分母均为同一公司、同一来源表中已明确识别的相关产品，不能跨 OPP 订单与业绩订单混算。
- 开源产品：OPP 订单表内产品按开源产品统计，并按真实产品名称展示构成；业绩订单来源只有在产品名称或已解码主数据明确支持时才纳入，不能用内部选项 ID 猜名称。
- 全部 OPP 订单的销量和金额另行作为 `oppOrderQuantity` / `oppOrderRevenue` 事实展示，不能与“已明确分类的门票”混为同一口径。
- OPP 订单与业绩回款缺少统一的跨表订单主键；两套开源产品数量和金额分别展示，不能相加后声称已经去重。
- 产品名称缺失的数量和金额按 OPP 订单与业绩订单分别单列。既没有产品明细、实时字段目录也无法确认上述扁平结构的 OPP 订单只进入完整性计数，不得使用未确认的顶层数量或金额字段补算。事实包必须分别给出子表记录数、经目录验证的扁平记录数和无法支持产品统计的记录数。

### 课程

- 课程堂数：课程开始日期 `date_1` 落在所选月份的记录数；课程名称为 `text_1`。
- 开课公司：课程举办方 `text_5` 的部门 ID 通过部门列表接口解码为公司名称；举办方缺失或无法解码时才允许回退到同课交付邀约订单所属公司的众数，并明确标注为回退口径。
- 参课老板：学员约课明细通过课程数据 ID `text_5` 关联课程，职位 `text_22` 严格等于“老板”的记录数；同时按全部已解码职位输出数量和占比，空职位单列“未填写”，不能把“老板助理”等包含词算成老板。
- 参课企业：只有约课记录存在可靠客户公司字段时才去重；清单未提供该字段时不得用约课记录数冒充企业数。
- 成交金额：从独立 `courseOrders` 集合按对应课程 `text_28` 关联当月课程，汇总合同金额 `num_1`；关联订单不要求签订日期与课程在同一月，且不得并入该月公司业绩排名。
- 成交率：使用“关联业绩订单数 ÷ 学员约课明细数”，并在答案中称为约课转化率。缺少任一可靠关联时保持为 0 并说明边界，不得用课程表旧汇总字段或未可靠同步的签到字段补算。

### 交付课程邀约与业绩

- 交付课程：课程类型包含“交付课程”且开始日期在所选月份。
- 邀约量：按当月交付课程 ID 与交付邀约关联表 `7452855` 的课程字段 `text_2` 逐课反查并计数；该表与课程分析使用的学员约课明细 `7642173` 分开，没有专用邀约记录时必须为 0，不能回退普通约课记录。
- 公司：按约课记录关联订单所属公司归集。
- 关联回款：同一公司内按关联订单 ID 去重后汇总约课记录金额 `num_3`。
- 该金额只是可追溯的“关联回款归集”，不能描述为财务分润、正式业绩分配或邀约/成交/交付三方权重。

### 商机与跟进质量

- “创建商机”按商机 `addTime` 和 `creatorId`；销售公司优先使用商机公司字段，缺失时才使用用户部门。
- 预计金额：`num_1`；赢单：阶段 `text_17` 解码后为“赢单”；赢单金额只使用 `num_14`，缺失时不得用预计金额替代。
- 跟进目标业务固定为销售机会（业务类型 `301`）。`communicate/list` 的 `text_5` 在实际查询与返回中承载关联业务记录 ID，因此必须先取得所选月份创建的商机，再按“跟进日期 `date_1` + 每个实际商机 ID 的 `text_5`”逐商机查询并去重；不得把字面量 `301` 当作关系 ID。没有直连关系时不按同客户回退，避免同一客户的多个商机互相串挂跟进。
- 事实层只给出阶段、金额、跟进次数、最后跟进日期、沉默天数、下一步动作信号、决策人信号和有效内容信号。
- “有效但被遗忘”候选规则：活动阶段、预计金额大于 0、存在中高意愿或有效跟进内容，并且至少 14 天未跟进。
- 不生成任意加权质量分，也不把规则信号描述为正式绩效、预测成交概率或系统认定。

## 证据边界

- 每个事实行保留来源 `evidenceRef`；回答通常无需展示内部 ID，但所有数字必须能回溯。
- 脱敏跟进片段只供当前 Codex 判断需求、阻力和下一步，不得逐字出现在最终答案或图表中。
- 没有客户级统一主键、正式分润字段或完整产品分类时，必须明确说明无法确认。
