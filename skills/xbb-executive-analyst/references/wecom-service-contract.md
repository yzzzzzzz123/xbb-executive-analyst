# 国内版企业微信智能机器人服务合同

## 正式接入方式

- 面向国内版企业微信普通员工，使用客户端“工作台 → 智能机器人 → 手动创建 → API 模式创建 → 使用长连接”。不要求企业管理后台、自建应用或超级管理员；若企业策略隐藏或禁止创建入口，才需要管理员开放。
- 正式传输只使用企业微信官方 `@wecom/aibot-node-sdk` WebSocket 长连接，以 Bot ID 和 Secret 认证。国内版默认地址是 `wss://openws.work.weixin.qq.com`。
- 服务主动建立出站连接，不监听业务 HTTP 端口，不要求公网 IP、域名、HTTPS 回调、反向代理、Token、EncodingAESKey 或 ReceiveId。
- Bot Secret 使用 Windows DPAPI CurrentUser 保护并保存在仓库外。一个 Bot ID 同时只运行一个正式连接；后台任务与人工前台调试不得并行。
- bundled 本机部署入口必须先做不回显 Secret 的单次鉴权检查；鉴权失败只显示阶段和企微错误码并允许重新输入。鉴权成功后才进入五分钟 USERID 绑定、集团只读策略写入以及登录计划任务安装，任何一步失败都不得伪报部署完成。

## 身份识别与访问控制

- 消息中的 `from.userid` 是唯一授权键。不得按姓名猜测，也不得把通讯录显示值当作实际回传值。
- 初次部署可运行 bundled 一次性识别入口。它仅接受本机随机生成、五分钟有效的完整绑定口令，只在本机标准输出显示命中的 USERID，不加载访问策略、模型或销帮帮数据，并在成功或超时后断开。
- 正式服务启动前必须建立访问策略。默认按精确 USERID 授权；部署者可以在策略中显式启用保留键 `*`，让机器人可触达范围内的任意用户获得集团全部公司只读权限。精确 USERID 规则优先于通配规则，实际 USERID 仍用于 Thread 与工具调用隔离。没有精确规则且未启用通配规则的用户在模型和销帮帮查询前失败关闭；公司级授权必须在模型调用前和 runner 调用时双重强制。
- SDK debug 日志必须关闭。服务日志不得记录消息正文、完整帧、USERID、事实包、跟进摘录、Secret、模型 Key 或销帮帮凭证。
- 允许在仓库外写入有大小上限的状态 JSONL，但字段只能包含时间、固定状态枚举、传输类型、随机服务代际 ID、重试次数和非负阶段耗时；不得写入 Thread ID、端口、用户、消息正文、图表内容或业务事实。独立服务租约也必须位于仓库外并原子覆盖，只能包含固定 schema、服务名、`starting`/`running`/`stopped` 状态、进程号、随机代际 ID、状态开始时间和更新时间，不得包含凭据、用户或经营数据；租约只是进程事件循环存活信号，状态日志中同代际的 `ready` 才代表已通过企业微信认证。

## 消息与流式回复

- 以 `msgid` 做十分钟内存排重；同一消息重投不得重复调用模型或 runner。
- 只读取文字、语音转文字和图文混排中的文字。图片、文件、视频及下载地址不进入模型。
- 首次回复沿用收到帧的 `headers.req_id`，生成唯一 stream id，并在调用 Codex Agent 前发送“正在识别问题范围和分析维度”的真实运行状态，`finish=false`；问候语不应伪称已经查询销帮帮。
- 进度使用同一 stream id 覆盖显示，仍为 `finish=false`。查询阶段展示已识别的期间、授权范围内实体、数据域、当前月份、完成月份数、实时/五分钟加密缓存来源、跨月汇总及隐私/完整性校验；分析阶段展示将比较的真实经营维度；图表阶段展示实际选定的图形类型及生成/上传状态。只展示桥接层确认的阶段，不转发 Codex commentary、内部推理、工具参数 JSON、业务数字或事实明细。
- 每条进度必须是老板手机上可直接理解的完整短状态，不是增量片段。45 秒心跳应保留最近的具体阶段并追加已用时，不能退化成笼统的“仍在分析”；快速连续事件只发送当前最新阶段，避免排队拖慢最终答复。最终答复使用同一帧和 stream id 返回完整内容，`finish=true`，UTF-8 长度不得超过 20480 字节。
- 每个问题都必须交付可独立阅读的文字答复，图内文字不能替代消息正文；销帮帮经营答复最多随附一张经营分析 PNG，支持同一张图片中的多个独立子图。两个及以上有效维度或宽泛问题必须出图；经营图由原生 ultra 子 Agent 执行 `xbb-executive-chart`，主 Agent 复核。图片显示实际图形、计算验证的发现与证据注释，不用占位状态卡代替。没有合格图表或渲染失败时仅回复文字。生成、上传和主动图片发送分别做有界重试；桥接层优先使用官方媒体上传与主动图片消息发送，失败或客户端不支持时回退到最终流式消息的 `msg_item`。图片只在内存生成，不落盘，原图不得超过企微 10MB 限制。
- 发送首次状态失败时不得调用模型或 runner；最终回复失败时保留内存排重状态，企微重投可重发相同最终结果及图片。即使首次图片已通过独立媒体消息成功发送，去重缓存也要保存图片项，不能让同一 `msgid` 的最终重投退化为纯文字。
- 通用问题输出直接、易懂的文字答复且 `chart` 固定为 `null`，不强制经营图片；经营问题逐项输出有证据的文字分析，有合格规格时由桥接层随附经营图。任何经营图都不得绕过同轮 `xbb-executive-chart`。任何模式都不上传事实包、跟进证据或 CRM 附件。已取得完整可用事实时，模型拒答、结构错误或超时由同一事实视图的确定性答案接管；实时源仍不可用时返回可执行的自动恢复状态，不使用陈旧数据、样例或固定经营数字。

## 连接生命周期

- 使用官方 SDK 自动认证、心跳和指数退避重连；正式配置的最大重连次数为 `-1`，直到人工停止进程。
- 认证成功只输出不含业务数据的 `ready` 状态；连接错误、断开和重连日志只输出固定状态及重试次数，不输出 SDK 原始错误或消息帧。
- 第一层是进程内连接看门狗：服务开始连接以及每次 `disconnected`、`reconnecting` 或连接错误后，只启动同一个连续 120 秒未认证窗口；重复重连不得重置或延长截止时间，收到 `authenticated` 才能清除。整个启动流程另有 90 秒硬截止；窗口或启动截止到期必须记录受控状态，关闭 SDK 与 App Server、停止租约、释放实例锁并以非零代码退出。SIGINT/SIGTERM、App Server fatal 或 runner 进程树无法确认回收时走同一幂等退出函数，fatal/信号清理和 App Server 终止各受 10 秒硬截止；失败以非零代码退出，不能只设置退出码后留下仍占用事件循环的失效进程，也不能让迟到资源重新进入运行态。
- 第二层是独立进程租约看门狗：主进程在初始化前写入随机代际的 `starting` 租约，运行时就绪后切换为 `running`，此后每 30 秒原子刷新；独立隐藏计划任务每 5 分钟检查，连续 180 秒没有有效 `running` 租约时重启主任务，合法 `starting` 只享受固定 300 秒宽限。看门狗读取的绝对路径必须与运行时最终解析的 `serviceLeasePath` 完全一致，不能在安装器中另写一个可能分叉的默认路径。企业微信 WebSocket 短断由进程内指数退避重连处理，不得触发这一层；正常异步长查询不会阻断租约，只有 Node 事件循环卡死、进程假活或持续写租约失败才会触发外部重启。看门狗与主任务使用同一受限 Windows 用户，外部脚本不得读取 Bot Secret、Thread 或经营事实。
- 外部判活必须同时核验准确的主任务名、绝对执行文件、完整参数、精确 Description、任务状态、租约 schema、服务名、状态、正整数 PID、进程创建时间与合理 UTC 时间；CIM/WMI 读取必须包含当前维护进程 sentinel，ScheduledTasks cmdlet 与 Task Scheduler COM 必须给出一致任务快照，任一来源不确定都失败关闭。未来时间、损坏 JSON、错误服务名或陈旧租约都不得视为健康。启动宽限不得依赖计划任务 `LastRunTime`。停止时必须先为严格匹配的服务根及白名单 App Server 后代逐一取得并核验 PID、创建时间与可执行文件的原生进程句柄，再先根后子终止；持有根句柄期间重复扫描新生后代，任何未知后代或句柄不匹配都失败关闭。目标退出后还须连续两次获得健康的空 CIM 快照。租约 PID 缺失或损坏时，只允许唯一且完整匹配当前任务动作的进程进入相同自愈路径；多候选、其他代际或身份不确定必须保持围栏。启动后必须确认不同于旧实例和看门狗标记的新代际 `running`，不能仅因 `Start-ScheduledTask` 未报错就宣称恢复成功。
- 主任务通过登录触发器和失败后 3 次一分钟间隔重启处理进程死亡，不得再配置周期性重复启动；必须显式使用 `IgnoreNew`，防止人工重复启动影响运行中的长查询。外部看门狗是每 5 分钟运行一次的独立任务，自身也使用 `IgnoreNew` 和有限执行时长；它只负责主任务仍显示 `Running`、但租约已失效的假活场景，不得使用 `StopExisting` 或创建并行 Bot 实例。
- 两个计划任务都直接执行仓库外生成的 `nodew.exe`：它是当前已安装 `node.exe` 的逐字副本，仅把 PE Subsystem 从 Console 改为 Windows GUI，并按源文件 SHA-256 自动更新。主任务固定传入 `--managed-config` 的仓库外绝对配置路径；进程加载配置前清除继承的全部 `XBB_*` 覆盖，避免租约、状态和凭据路径漂移。主任务不得包一层长期 PowerShell/WSH/自定义宿主；由于 Node 本身仍是任务根进程，停止主任务时必须同时结束 Node 与 App Server，避免同一 Bot ID 出现孤儿连接。外部看门狗允许使用短生命周期 Node 启动器，但必须以 `windowsHide=true`、`shell=false` 和非控制台标准流启动维护 PowerShell，且必须等待并透传退出码；Task Scheduler 不得直接执行控制台子系统的 PowerShell。
- 安装、升级、卸载和看门狗必须使用不依赖 TaskName 的产品级跨 Windows 会话全局锁，并扫描所有 TaskPath/TaskName 下动作指向本产品受管配置的任务变体；稳定产品身份必须识别不同旧工作区中的 direct node/nodew、历史 PowerShell 启动器、旧版 PowerShell watchdog 和新版隐藏 Node watchdog，动作路径必须是规范化的全限定 Windows drive/UNC 路径，drive-relative、root-relative、归属不明或多实例状态必须失败关闭。产品任务快照必须由 ScheduledTasks cmdlet 与 Task Scheduler COM 交叉确认，空结果须跨两轮确认。安装或升级须验证双任务归属并导出 XML 备份，再禁用并停止外部看门狗、禁用并停止主任务；必须等待严格匹配的旧进程退出，并在停止前、注册后及失败回滚恢复旧任务前恢复旧版及新版租约目录内的 runner 隔离标记，避免更名任务、周期触发器或孤儿进程拉起旧实例。每次禁用、启用、停止或启动任务前必须即时复核 ownership。完成两个任务注册后先启动主任务、再启动看门狗，并以新代际 `running` 租约和同代际 `ready` 验证真实认证。看门狗恢复触发器不得设置会在若干年后到期的重复周期。任何安装、启动或认证步骤失败时，先清理半安装任务，再恢复旧任务 XML 与原启用状态，仅重启升级前原本运行的任务并验证恢复运行态；这只回滚任务定义，不回滚同一工作区内已经变更的代码。只停止主任务会被失败重试或外部看门狗重新拉起；计划维护必须先禁用两项任务，卸载必须先停止并注销看门狗、再停止并注销主任务。卸载任务不等于删除 DPAPI 配置、访问策略、状态或租约文件。
- 两层看门狗都依赖 Windows、当前用户会话、Task Scheduler、本机磁盘和电源仍可用。当前两个任务均为同一用户的 `Interactive`/`Limited` 登录任务：锁屏不会停止已登录会话，但注销后、Windows 重启而用户尚未登录、睡眠、休眠、关机或断网时机器人仍会离线；这不是开机前运行的 Windows Service，也不是跨主机高可用。若要求全年无人值守，必须另行部署常开主机和经过 DPAPI/Codex 登录验证的专用服务账号；同一 Bot ID 的双机主备还必须有跨机租约和 fencing，禁止双活连接互相踢下线。

## 模型与工具

- 默认模型入口是当前 Windows 用户已使用 ChatGPT 登录的本机 Codex App Server，不配置独立 OpenAI API Key 或模型端点。服务启动时必须校验登录模式为 ChatGPT。
- 桥接进程启动一个回环地址、capability-token 鉴权的 Codex App Server，并按授权主体维护持久 Thread；不得每条消息执行一次 `codex exec`，不得把 Codex 当无状态 JSON 生成器。
- 机器人统一使用 `gpt-6-astra` 与 `xhigh` 推理强度。顶层是通用 Codex Agent：普通问答、写作、解释、翻译、方案、代码和其他知识工作不因与经营无关而拒绝；只有公司经营、业绩、产品、课程、交付、商机等问题才进入 `xbb-executive-analyst`，并在同一个 Turn 同时加载 `xbb-executive-chart` 辅助依赖；这不是第二 Agent 或第二模型。所有普通与经营轮次使用配置的 xhigh，不因是排名、数量或占比问题自动降档。路由规则属于可信服务配置，不得由用户消息修改；不得为提速换成较弱模型。经营问题不得跳过完整 Skill RAG。年度范围在查询前展开，按明确 metrics 选择必需表和字段；生产关闭粗域预取。新经营轮次只继承有界用户意图，旧业务事实不进入新轮次。
- 同一授权主体已有 Turn 运行时，能力路由一致的后续消息必须使用 `turn/steer` 追加到当前 Turn，并携带匹配的 `expectedTurnId`。若 Turn 尚未启动且可信桥接层仍在预取，改变范围的最新消息必须先取消旧订阅并立即接管；对“改成只看9月”这类省略式修正，只能携带有界原问题语义帮助新 Turn 确定业务域，不得携带旧范围事实。追加内容要明确标为用户追问/修正；与原问题冲突时以最新消息为准。成功追加后，旧流式消息用简短交接说明结束，最终结论和图表只回复到最新消息；连续追问逐次把最终答复所有权移交给最新消息，不能重复发送同一最终结果。成功追加后重新计算该能力路由的生成超时。若新消息需要切换通用/经营能力路由，由于活动 Turn 不能修改 Skill、沙箱和输出合同，应先提示已排队，等当前 Turn 结束后自动以新 Turn 处理，不返回忙碌拒绝。
- 服务启动时先写 `starting` 租约，再完整读取 `xbb-executive-analyst`、`xbb-executive-chart` 与运行合同，按 Markdown 章节切块、生成内容摘要并建立只读内存 RAG 索引，同时启动 App Server。启动阶段只同步校验本地知识索引，不按访问策略逐用户执行模型预热；历史 Thread 仅登记，新授权主体在首条消息时惰性创建，已有主体也在首条消息时惰性恢复。运行时就绪后租约切为 `running` 并开始企业微信认证，`ready` 只代表同代际已认证。桥接层按当前问题和上一轮成功路由区分通用 Turn 与经营 Turn。通用 Turn 只传通用能力路由和用户问题，不注入经营/辅助图 Skill 或 RAG、不预取事实且服务端拒绝 `query_xbb`；经营 Turn 在同一输入中显式附带两个 Skill、不可省略的核心边界、按问题检索命中的原文规则、可信日期、授权范围和不可信用户问题，不整本重复拼接合同。可信桥接层可从经营问题确定月份和数据域，并在模型 Turn 前通过同一受控 `query_xbb` 网关实时预取事实；事实不足或需要实体消歧时保留模型动态调用。经营事实不得从 Thread 历史或 RAG 复用。
- 每个 Turn 使用结构化最终输出：`answer` 是必需且非空、可独立阅读的中文文字答复；简单问题简短答清，复杂问题逐项给出结论、关键数字、依据和限制，有图时仍保留完整正文，`chart` 是可选的单张真实经营图最小规格；图表字段 Schema 和运行时严格验证由辅助图 Skill 单一维护，桥接层验证后再渲染。经营图验证或渲染失败时仍返回真实文字结论，图表暂不可用时只保留文字，不生成结论速览或占位图，不能生成替代假经营图。
- 子进程环境使用白名单，不继承企微 Secret、销帮帮凭证、API Key、Token 或其他业务密钥。生产运行没有 `chat-completions` 兼容分支、mock、样例或固定答复回退。
- 模型只注册 `query_xbb` 一个业务动态工具；这不限制 Codex 的通用问答与系统实际提供的通用只读能力。只有经营 Turn 才能调用该工具，桥接层必须在服务端按本轮能力路由再次校验。桥接层预取与模型动态调用共用同一工具网关；所有参数经过白名单校验，且事实包在传给模型前再次验证实时只读来源、隐私标志和 SHA-256 完整性。
- 同一 Turn 中动态工具参数与桥接层预取完全相同时直接复用已校验结果；大型查询不得重复取数。跨月包只包含完整管理聚合、月度趋势、排名和有界下钻候选，目标是让模型作经营判断和组织表达，而不是承担大规模过滤、连接或求和。
- `ready` 事实已取得时，模型技术性拒答、无效结构、空结果或生成超时由同一已校验视图生成有界确定性答案，并使未知状态 Thread 失效；runner 在 API 和进程级有界重试后仍失败时只返回真实自动恢复状态，不使用陈旧数据。任何结果都必须有文字答复；有合格经营图时随附图片，明文事实包在 `finally` 中删除。
