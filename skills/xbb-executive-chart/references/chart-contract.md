# 经营辅助图规格合同

这是 `xbb-executive-chart` 和项目确定性渲染器共同遵守的最小合同。最终 JSON 必须是下列六种判别结构之一；所有对象都拒绝未列出的字段。

## 共同字段

模型新生成的每一种图都必须包含以下字段。运行时兼容历史规格：`focus`、`finding` 允许省略，省略时视为 `null`；其余必填字段和原有长度上限保持不变。显式无效的 `finding` 不被当作缺省值。

- `type`：`bar`、`stacked-bar`、`line`、`donut`、`scatter` 或 `funnel`。
- `title`：非空，说明对象和指标，不在标题里塞结论；手机阅读建议不超过 20 个中文字。
- `subtitle`：可为空；有值时说明期间、范围、截至时间或必要分母。
- `insight`：保留的非空兼容输入字段，模型建议填 `"由finding生成"`。发布前程序必定覆盖，不能借此输入字段发布自由数字断言；最终文案由下述关系计算或兼容概述生成，上限仍为 160 个字符。
- `note`：可为空；只写会影响解释的真实口径限制。
- `focus`：`null` 或严格的 `{ "series": string, "category": string }`；模型建议填 `null`。非空 `finding` 会将它归一化为 `finding.subject` 的系列与类别；若输入非空却指向不同位置，拒绝整张图。无 `finding` 时清空重点。
- `finding`：`null` 或下述结构化关系。模型只选关系和图内引用，不输入新的计算结果、分母数值或发现文案。

文字结论、因果解释与行动建议仍由主 Skill 的 `answer` 承担。图表规格不得包含建议、因果断言、预测、电话、邮箱、凭据、客户跟进原文、颜色、CSS、SVG、HTML、脚本、URL 或文件路径。必要口径 `note` 必须保留，文案长度建议不是删除限制条件的理由。

## 结构化发现与证据位置

非空 `finding` 严格使用以下三个字段；`subject` 是要强调的数据位置，`baseline` 是比较基准（仅 `share` 必须为 `null`）：

```json
{
  "relation": "difference",
  "subject": { "series": "指标", "category": "乙", "axis": "value" },
  "baseline": { "series": "指标", "category": "甲", "axis": "value" }
}
```

每个引用都必须明确包含 `series`、`category`、`axis`，不接受未知字段、数值副本或近似名称。名称与图内标签均清理首尾空白，再严格匹配：

- `bar`、`stacked-bar`、`line`：`series` 匹配已有 `series.name`，`category` 匹配已有 `categories`，`axis` 必须为 `"value"`。
- `donut`、`funnel`：`series` 必须为 `""`，`category` 匹配已有 `items.name`，`axis` 必须为 `"value"`。
- `scatter`：`series` 必须为 `""`，`category` 匹配已有 `points.label`，`axis` 为 `"x"` 或 `"y"`。不比较不同坐标轴；`size` 没有独立单位合同，不能用作发现引用。
- 两个引用不得是同一数据位置；比较必须使用同一坐标轴、格式和单位。非空 `focus` 的两个字段同样必须严格匹配已有数据，不能与 `subject` 矛盾。

| `relation` | 适用图形 | 程序计算与门槛 |
| --- | --- | --- |
| `difference` | 全部六种 | 主体减基准，生成高/低/相同和绝对差值；百分比差值使用“个百分点”。 |
| `period-change` | `bar`、`line` | 同一系列且基准在图示位置上早于主体；计算差值。非百分比另算 `(主体－基准) / 基准 × 100%`，基准须大于零；百分比只算百分点变化。 |
| `share` | `donut`、`stacked-bar` | 主体除以图内完整可见组成项之和；环形取全部项目，堆叠取主体所在类别的全部系列。分母须大于零，文案明确写出图示分母；`baseline` 为 `null`。 |
| `retention` | `funnel` | 较晚主体阶段 / 较早基准阶段；基准须大于零、主体不得大于基准。 |
| `loss` | `funnel` | `(较早基准阶段－较晚主体阶段) / 较早基准阶段`，门槛同留存。 |

例如中间阶段 40、完成阶段 20，可选择 `retention` 并引用“完成”为主体、“中间”为基准，得到保留 50%；它不是自动用首阶段作分母，也不自动将最大值作为发现。渲染器中独立标明基准的整体或相邻阶段指标可以同时存在，不应误读为同一比较。

程序生成的 `insight` 以“图内计算”开头，`focus` 精确指向主体；不从 `insight` 或 `answer` 的自然语言猜关系。显示长名称时可以截短；发生显示身份碰撞则附加图内系列/类别/项目/点的位置编号，原始标签和引用不变。散点差值明确标注所比较的 x/y 轴。

### 数值与失败处理

- 从通过合同的 JavaScript `Number` 十进制表示做有理数计算，避免 `0.3 - 0.1` 等运算尾差成为发现。一般展示最多保留约 8 位有效数字，派生比率为便于手机阅读保留约 4 位，非精确展示带“约”；不将非零小数无提示地显示成零。该过程不能恢复 JSON 解析前已丢失的原始精度。
- 任一派生结果超出有限数字范围、非零结果下溢、缺失引用、零分母、格式不一致或不支持的关系，均拒绝整张图；现有答复解析保留文字并将 `chart` 降级为 `null`。不会把无效 `finding` 偷换成兼容概述。
- `number` 的单位不得伪装为 `%` / 百分比 / 百分点来参与关系计算，应改用 `percent`。`money` 使用元；百分比差值是百分点，构成/留存/流失是比率。
- `percent` 构成的 `share` 要求十进制值精确合计 100；旧构成合同容许的 ±0.5 个百分点只支持无 `finding` 的兼容图，不能作为精确占比关系的分母。
- `finding: null` 或历史缺失字段会覆盖原 `insight` 为“兼容概述”：只陈述图内首/末项目的可见值，散点只概述点数及首点坐标；同时清空 `focus`。它不是经验证的关系发现，原自由断言绝不原样发布。归一化后的规格再次经过解析或渲染，结果保持相同。

### 证明范围

这些检查只证明图内引用、格式与计算一致，不证明原始数字已绑定完整事实源，不证明真实时间标签、总体完整性、同一观察粒度或同一批对象。`period-change` 只验证图示顺序；不能把普通类别排序自动解释成真实时间。主经营 Skill 仍须对照当轮事实包核实期间、范围、同口径分母、同批次漏斗与来源，不得把合同通过当作这些业务语义已获认证，更不能据此生成因果或预测。

## 分类型字段

### `bar` 与 `stacked-bar`

除共同字段外，必须包含：

- `categories`：2—10 个非空且唯一的标签。
- `series`：1—4 个非空且唯一的系列；每个系列为 `{ "name": string, "values": number[] }`，数值数量必须与 `categories` 相同。
- `valueFormat`：`number`、`money` 或 `percent`。
- `unit`：`number` 的业务单位，例如“家”“人”“单”；`money` 和 `percent` 时必须为空。`money` 原始数值一律以元为单位，由渲染器自动显示元、万或亿。

数值必须有限且不小于零。`bar` 用于排序或类别比较；`stacked-bar` 的各系列必须是同一总量的可加组成项。`stacked-bar` 使用 `percent` 时，每个类别的各系列必须合计 100，只容许 ±0.5 个百分点的舍入差。

### `line`

字段与条形图相同，但 `categories` 可包含 2—30 个按时间升序排列的标签。数值可为负；若 `valueFormat` 是 `percent`，仍必须位于 0—100。2—3 个时间点虽然合同可表达，但本 Skill 默认改用条形图或文字，除非这些点确实构成连续时间比较。

### `donut`

除共同字段外，必须包含：

- `items`：2—8 个 `{ "name": string, "value": number }`；名称非空且唯一，数值有限且不小于零。
- `valueFormat`、`unit`：含义与条形图相同。
- `centerLabel`：环形中心合计的简短名称。

`items` 必须属于同一分母。渲染器会从这些原始数值计算构成占比；若 `valueFormat` 为 `percent`，输入值本身就是百分点，各项必须合计 100（只容许 ±0.5 个百分点的舍入差），图例不重复显示第二份相同百分比。

### `scatter`

除共同字段外，必须包含：

- `points`：2—40 个 `{ "label": string, "x": number, "y": number, "size": number }`；标签非空且唯一，`x`、`y` 必须有限，`size` 必须有限且不小于零。
- `xLabel`、`yLabel`：两个坐标的业务含义。
- `xFormat`、`yFormat`：各自为 `number`、`money` 或 `percent`。
- `xUnit`、`yUnit`：`number` 坐标可用的业务单位；对应格式为 `money` 或 `percent` 时必须为空。

所有点必须使用同一观察粒度、期间、范围和过滤条件。`size` 只有在第三个指标会改变解释时才使用；否则统一填 `0`。

### `funnel`

字段为共同字段，加上 `items`、`valueFormat` 和 `unit`。`items` 包含 2—8 个按真实业务阶段排列的名称和值；值必须有限、非负且从前到后不增加。

## 百分比与空值

- `percent` 一律使用 0—100 的百分点，`37.5` 才表示 `37.5%`。
- `0` 是经过确认的真实零；缺失、未知或未纳入统计不能写成 `0`。
- 不允许 `NaN`、`Infinity`、字符串数字或混合单位。

## 最小示例

```json
{
  "type": "stacked-bar",
  "title": "公司回款结构",
  "subtitle": "合同示例｜以下均为虚构数字",
  "insight": "由finding生成",
  "note": "示例只比较已分类课程与咨询回款，非真实经营事实",
  "focus": null,
  "finding": {
    "relation": "share",
    "subject": { "series": "咨询", "category": "公司乙", "axis": "value" },
    "baseline": null
  },
  "categories": ["公司甲", "公司乙"],
  "series": [
    { "name": "课程", "values": [100000, 80000] },
    { "name": "咨询", "values": [20000, 60000] }
  ],
  "valueFormat": "money",
  "unit": ""
}
```

该示例生成“公司乙咨询占该类别图示合计约 42.86%（分母 140000 元）”的计算发现，并聚焦公司乙的咨询组成项；它没有计算两家公司占比的差值。不要添加 `items`、`points`、坐标字段或其他无关空字段。
