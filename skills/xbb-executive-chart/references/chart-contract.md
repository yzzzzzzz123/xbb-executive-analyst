# 经营辅助图规格合同

这是 `xbb-executive-chart` 和项目确定性渲染器共同遵守的最小合同。提交 `validate_xbb_chart` 的完整 `spec` 必须是下列六种单图结构或 composite 综合结构之一；所有对象都拒绝未列出的字段。企业微信 Agent 校验并检查手机预览后，最终 `chart` 使用校验工具给出的 `{type:"validated",id:...}` 引用，由桥接层在当前事实和追问版本内解析回原规格；不用再次抄写全部字段。引用不属于渲染器的图形类型，不能拿引用作为新的 `spec`。

## 共同字段

模型新生成的每一种单图都必须包含以下字段。运行时兼容历史规格：`focus`、`finding` 允许省略，省略时视为 `null`；`findings` 允许省略，此时采用有效的单条 `finding` 或空数组。其余必填字段和原有长度上限保持不变。显式无效的关系不被当作缺省值。

- `type`：`bar`、`stacked-bar`、`line`、`donut`、`scatter` 或 `funnel`。
- `title`：非空，说明对象和指标，不在标题里塞结论；手机阅读建议不超过 20 个中文字。
- `subtitle`：可为空；有值时说明期间、范围、截至时间或必要分母。
- `insight`：保留的非空兼容输入字段，模型填 `"由finding生成"`。发布前程序必定覆盖，不能借此字段发布自由数字断言；归一化值来自首条关系的计算，或无关系时的可见数值概述，上限仍为 160 个字符。渲染器只从结构化关系重新计算注释，不直接读取此输入字段。
- `note`：可为空；只写会影响解释的真实口径限制。
- `focus`：`null` 或严格的 `{ "series": string, "category": string }`；模型填 `null`。程序按首条关系的 `subject` 归一化重点；若输入非空却指向不同位置，拒绝整张图。无关系时清空重点。
- `finding`：`null` 或下述结构化关系。模型只选关系和图内引用，不输入新的计算结果、分母数值或发现文案。
- `findings`：0—4 条非空结构化关系，按阅读顺序排列，每条结构与 `finding` 相同，不接受文案、结果数字、额外字段或重复关系。数据充分的每个问题维度建议选择 2—4 条互补关系，例如完整月变化、峰值、排名差距、贡献集中度。`finding: null` 且数组非空时，程序采用首条；两者均非空时 `finding` 必须与首条完全一致。空数组加有效的 `finding` 按单条关系兼容。

主 Skill 的 `answer` 负责逐维度完整分析及有证据的解释。图中显示由 `findings` 计算出的多条关键关系和证据注释；主发现先读，其余关系依次呈现。图表规格不得包含建议、因果断言、预测、电话、邮箱、凭据、客户跟进原文、颜色、CSS、SVG、HTML、脚本、URL 或文件路径。必要口径 `note` 必须保留，文案长度建议不是删除限制条件的理由。

## 结构化发现与证据位置

非空 `finding` 和 `findings` 中每一项严格使用以下三个字段；`subject` 是要强调的数据位置，`baseline` 是比较基准。`share`、`top-share`、`maximum`、`minimum` 的 `baseline` 必须为 `null`，其他关系必须给出有效引用：

```json
{
  "relation": "difference",
  "subject": { "series": "指标", "category": "乙", "axis": "value" },
  "baseline": { "series": "指标", "category": "甲", "axis": "value" }
}
```

每个引用都必须明确包含 `series`、`category`、`axis`，不接受未知字段、数值副本或近似名称。名称与图内标签均清理首尾空白，再严格匹配：

- `bar`、`stacked-bar`、`line`：`series` 匹配已有 `series.name`，`category` 匹配已有 `categories`，`axis` 必须为 `"value"`。
- `donut`、`funnel`：`series` 必须为 `""`，`category` 匹配已有 `items.name`，`axis` 必须为 `"value"`。
- `scatter`：`series` 必须为 `""`，`category` 匹配已有 `points.label`，`axis` 为 `"x"` 或 `"y"`。不比较不同坐标轴；`size` 没有独立单位合同，不能用作发现引用。
- 两个引用不得是同一数据位置；比较必须使用同一坐标轴、格式和单位。非空 `focus` 的两个字段同样必须严格匹配已有数据，不能与 `subject` 矛盾。

| `relation` | 适用图形 | 程序计算与门槛 |
| --- | --- | --- |
| `difference` | 全部六种 | 主体减基准，生成高/低/相同和绝对差值；百分比差值使用“个百分点”。 |
| `period-change` | `bar`、`line` | 同一系列且基准在图示位置上早于主体；计算差值。非百分比另算 `(主体－基准) / 基准 × 100%`，基准须大于零；百分比只算百分点变化。仅当本条关系的 `subject` 或 `baseline` 类别含 `MTD`（忽略大小写）、“截至”“未完月”“月累计”时拒绝。图中其他位置、总副标题或口径含 MTD 不使两个完整端点的比较失效。 |
| `maximum` / `minimum` | `bar`、`line` | 主体必须为所在系列全部可见类别的真实最大/最小值；程序显示数值及所示项数，并列须明示。全相等序列拒绝；不允许把任意主体写成峰谷。`baseline` 为 `null`。 |
| `share` | `bar`、`donut`、`stacked-bar` | 主体除以图内全部可见组成项之和；条形取主体所在系列全部类别，环形取全部项目，堆叠取主体所在类别全部系列。分母须大于零，文案明确写出所示合计；`baseline` 为 `null`。可见项必须是业务上有意义的可加组成项。 |
| `top-share` | `bar`、`donut` | 按值降序排列，`subject` 指向第2或第3项，程序合计截至该项的前2/3项并除以全部可见项合计。必须保留其他项；排名截止处有并列则拒绝，不能任意截断。条形图必须只有一个系列。`baseline` 为 `null`，不得输入前N合计或占比的数值副本。 |
| `retention` | `funnel` | 较晚主体阶段 / 较早基准阶段；基准须大于零、主体不得大于基准。 |
| `loss` | `funnel` | `(较早基准阶段－较晚主体阶段) / 较早基准阶段`，门槛同留存。 |

例如中间阶段 40、完成阶段 20，可选择 `retention` 并引用“完成”为主体、“中间”为基准，得到保留 50%；它不是自动用首阶段作分母，也不自动将最大值作为发现。渲染器中独立标明基准的整体或相邻阶段指标可以同时存在，不应误读为同一比较。

例如年度曲线同时显示 1—8 月完整月和“9月MTD”，仍可选择 `subject: 8月`、`baseline: 7月` 计算完整月变化；选择 `subject: 9月MTD`、`baseline: 8月` 则拒绝。主 Skill 必须分别核对这两个端点的实际日期与对应口径；若端点本身只覆盖部分月份，即使标签遗漏 MTD，也不能声称完整月环比。无需为比较 7 月和 8 月而删掉同图中的 9 月 MTD。

渲染器逐条从关系及其引用值重新计算可读注释，在图旁按 A—D 顺序显示，并让 `focus` 精确指向首条主体。图中不显示“图内计算”“兼容概述”等内部措辞，也不从 `insight` 或 `answer` 的自然语言猜关系。数字的正负号、小数、单位、百分号及完整的证据引用标签尽量保持在同一行。显示长名称时可以截短；发生显示身份碰撞则附加图内系列/类别/项目/点的位置编号，原始标签和引用不变。散点差值明确标注所比较的 x/y 轴。

### 数值与失败处理

- 从通过合同的 JavaScript `Number` 十进制表示做有理数计算，避免 `0.3 - 0.1` 等运算尾差成为发现。一般展示最多保留约 8 位有效数字，派生比率为便于手机阅读保留约 4 位，非精确展示带“约”；不将非零小数无提示地显示成零。该过程不能恢复 JSON 解析前已丢失的原始精度。
- 任一派生结果超出有限数字范围、非零结果下溢、缺失引用、零分母、格式不一致、不支持的关系、数组超限、重复关系、主发现矛盾或单条派生注释超过 160 个字符，均拒绝整张图；现有答复解析保留文字并将 `chart` 降级为 `null`。不会把无效关系偷换成无发现的兼容图。
- `number` 的单位不得伪装为 `%` / 百分比 / 百分点来参与关系计算，应改用 `percent`。`money` 使用元；百分比差值是百分点，构成/留存/流失是比率。
- `percent` 构成的 `share` 和 `top-share` 要求十进制值精确合计 100；旧构成合同容许的 ±0.5 个百分点仍能支持无占比关系的图，不能成为声称精确占比的分母。
- `finding: null` 且 `findings` 为空，或历史字段都缺失时，程序覆盖原 `insight` 为可见值概述：只陈述首/末项目的可见值，散点只概述点数及首点坐标；同时清空 `focus`。这份兼容概述不显示为发现注释，原自由断言绝不原样发布。归一化后的规格再次经过解析或渲染，结果保持相同。

### 证明范围

这些检查只证明图内引用、格式与计算一致，不证明原始数字已绑定完整事实源，不证明真实时间标签、总体完整性、同一观察粒度或同一批对象。`period-change` 验证图示顺序并拒绝本条关系两端点中明确的未完整期间标记，不扫描其他数据点来决定这条比较是否可用；它不能识别所有省略标记的部分期间，也不能把普通类别排序自动解释成真实时间。`maximum`、`minimum`、`share`、`top-share` 的范围仅是图中可见值；若只展示部分对象，不能将其描述为集团最高值或集团贡献占比。主经营 Skill 仍须对照当轮事实包核实两个端点的完整日期、各自口径、范围、同口径分母、同批次漏斗与来源，不得把合同通过当作这些业务语义已获认证，更不能据此生成因果或预测。

## 分类型字段

### `bar` 与 `stacked-bar`

除共同字段外，必须包含：

- `categories`：2—10 个非空且唯一的标签。
- `series`：1—4 个非空且唯一的系列；每个系列为 `{ "name": string, "values": number[] }`，数值数量必须与 `categories` 相同。
- `valueFormat`：`number`、`money` 或 `percent`。
- `unit`：`number` 的业务单位，例如“家”“人”“单”；`money` 和 `percent` 时必须为空。`money` 原始数值一律以元为单位，由渲染器自动显示元、万或亿。

数值必须有限且不小于零。`bar` 用于排序或类别比较；`stacked-bar` 的各系列必须是同一总量的可加组成项。`stacked-bar` 使用 `percent` 时，每个类别的各系列必须合计 100，只容许 ±0.5 个百分点的舍入差。

### `line`

字段与条形图相同，但 `categories` 可包含 2—30 个按时间升序排列的标签。数值可为负；若 `valueFormat` 是 `percent`，仍必须位于 0—100。2—3 个时间点虽然合同可表达，但默认改用条形图或文字，除非这些点确实构成连续时间比较。有有效发现的趋势图附上全部所示期间的精确数值，不能只给末值和单一峰值。当前月须在类别及口径明确写明 MTD/截至日期；连接明确未完整期间的线段使用虚线，当前值标注 MTD。完整月的变化关系须另选完整月份。

### `donut`

除共同字段外，必须包含：

- `items`：2—8 个 `{ "name": string, "value": number }`；名称非空且唯一，数值有限且不小于零。
- `valueFormat`、`unit`：含义与条形图相同。
- `centerLabel`：环形中心合计的简短名称。

`items` 必须属于同一分母。渲染器会从这些原始数值计算构成占比；若 `valueFormat` 为 `percent`，输入值本身就是百分点，各项必须合计 100（只容许 ±0.5 个百分点的舍入差），图例不重复显示第二份相同百分比。

### `scatter`

除共同字段外，必须包含：

- `points`：2—40 个 `{ "label": string, "x": number, "y": number, "size": number }`；标签非空且唯一，`x`、`y` 必须有限，`size` 必须有限且不小于零。
- `xLabel`、`yLabel`：两个坐标的业务含义。
- `xFormat`、`yFormat`：各自为 `number`、`money` 或 `percent`。
- `xUnit`、`yUnit`：`number` 坐标可用的业务单位；对应格式为 `money` 或 `percent` 时必须为空。

所有点必须使用同一观察粒度、期间、范围和过滤条件。`size` 只有在第三个指标会改变解释时才使用；否则统一填 `0`。

### `funnel`

字段为共同字段，加上 `items`、`valueFormat` 和 `unit`。`items` 包含 2—8 个按真实业务阶段排列的名称和值；值必须有限、非负且从前到后不增加。

## 百分比与空值

- `percent` 一律使用 0—100 的百分点，`37.5` 才表示 `37.5%`。
- `0` 是经过确认的真实零；缺失、未知或未纳入统计不能写成 `0`。
- 不允许 `NaN`、`Infinity`、字符串数字或混合单位。

## 最小示例

```json
{
  "type": "stacked-bar",
  "title": "公司回款结构",
  "subtitle": "合同示例｜以下均为虚构数字",
  "insight": "由finding生成",
  "note": "示例只比较已分类课程与咨询回款，非真实经营事实",
  "focus": null,
  "finding": {
    "relation": "share",
    "subject": { "series": "咨询", "category": "公司乙", "axis": "value" },
    "baseline": null
  },
  "findings": [
    {
      "relation": "share",
      "subject": { "series": "咨询", "category": "公司乙", "axis": "value" },
      "baseline": null
    },
    {
      "relation": "difference",
      "subject": { "series": "咨询", "category": "公司乙", "axis": "value" },
      "baseline": { "series": "咨询", "category": "公司甲", "axis": "value" }
    }
  ],
  "categories": ["公司甲", "公司乙"],
  "series": [
    { "name": "课程", "values": [100000, 80000] },
    { "name": "咨询", "values": [20000, 60000] }
  ],
  "valueFormat": "money",
  "unit": ""
}
```

该离线虚构示例生成两条证据注释：公司乙咨询占该类别所示合计约 42.86%（合计 14 万元）；公司乙咨询比公司甲咨询高 4 万元。重点落在首条的公司乙咨询组成项。它没有计算两家公司占比的差值。不要添加 `items`、`points`、坐标字段或其他无关空字段。

## 综合图 composite

外层严格只包含 `type: "composite"`、`title`、`subtitle`、`note`、`panels`。三个文字字段沿用单图长度和安全约束，`title` 非空。`panels` 为 2—8 个上述完整单图规格，标题不得重复，不允许嵌套 composite。同类型与同数据的图不能仅更改标题、口径、重点或发现后重复放入以凑维度；程序排除这些文字和发现字段后检测重复数据。每个子图独立验证单位、分母和全部关系，任意子图无效则拒绝整张综合图。

先逐维度分析用户问题，再选择有表达力的图形与关系。只要问题超过一个分析维度，即至少涉及两件事，事实充分时就应生成覆盖这些维度的综合图；“今天业绩怎么样”这类宽泛分析也应拆成有证据的多个维度。明确的单一标量问题，例如某分公司今天的业绩金额，可以不出图。三个及以上维度须全部覆盖，不能只绘制三个裸图就算完成，也不固定凑满八项。每个数据充分的分区选择 2—4 条互补发现，按问题与文字答复相同的顺序阅读。

例如月度图呈现全部月份及完整月变化，区域图呈现排名差距和前两项贡献，产品图呈现构成与来源差距；同范围的可加总数字应能相互核对。超过八个细分子问题时，可将同指标、同单位、同粒度的对象作为系列或类别放入同一子图，仍须在文字逐项回答；无法诚实合图的剩余维度说明限制。范围和截止时间必须一致或明确标注各自口径，不能用缺失值或重复图凑覆盖。

综合图使用一个总标题和阅读目录，各子图全宽纵向分区，以 01—08 编号。每区保留自己的期间、数值、关系注释及统计限制，整体只显示一次来源；手机可直接读到关系及关键数值。图中显示经计算的关键关系，不直接显示输入 `insight`，也不生成无证据的结论、因果、建议、预测或文字占位卡。
